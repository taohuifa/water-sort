# 美术优化验收与存档规范

适用范围：本项目所有视觉/美术向优化（素材生成、渲染效果、UI 风格）。

## 核心原则

**"我认为可以了"不构成完成判定。** AI 的验收结论必须基于全量证据链，
且最终完成判定权在用户。

## 一、缺陷清单驱动（验收前）

1. 优化前先列出缺陷清单（编号 D1、D2…），每条含：现象、根因假设、验证手段。
2. 验收 = 逐条闭环（修复确认），不允许"整体看起来好了"这种印象式结论。

## 二、全量取证矩阵（验收中）

抽查不算验收。必须覆盖：

| 维度 | 要求 |
|------|------|
| 素材 | 全部颜色/变体逐张肉眼检查（AI 生成管线是概率性的，必须逐张验收） |
| 状态 | 每种颜色 × 每种出现形态（顶带/中带/底带/单格带/隐藏层） |
| 画面 | 逐瓶放大检查（不是只看一排或局部区域），覆盖菜单页 + 游戏页 + 选中态 |
| 场景 | 至少一个含全部 8 色 + 隐藏层的关卡；不足则换关补齐 |

**三重证据**，每项缺陷至少两种：

1. **数值证据**：像素采样。接缝/断层类缺陷两侧色差 ΔRGB < 8 判定不可感知；
   采样点必须覆盖左/中/右多个 x 位置，不能只采中心线。
2. **视觉证据**：≥8x 放大截图逐瓶检查（来源：`wx.mjs snap` 画布原生截图，
   1px = 0.5 游戏单位；禁用 MCP 截图做精细判断——有缩放与陈旧帧问题）。
3. **基准证据**：与参考图**同区域并排对比**（裁剪参考图对应部位 vs 游戏截图
   同部位，等比例并排），"接近参考"必须是测量结论，不允许印象分。

## 三、完成判定（验收后）

1. 出具验收报告（见存档规范），逐项给出 PASS / FAIL / 遗留。
2. 存在 FAIL 或未验证项 → 不得宣布完毕，继续修。
3. 全部 PASS + 遗留项经用户确认接受 → 才算完毕。
4. 用户提出新问题时，先定位到缺陷清单编号（或新增编号），不允许直接改。

## 四、存档规范

- 报告：`docs/art-acceptance/YYYY-MM-DD-<主题>.md`
  内容：缺陷清单、每条的修复说明与三重证据结论、验收截图路径、遗留问题、
  当前版本与参考图的差距自评。
- **报告必须用 Markdown 内嵌链接贴图**（`![说明](../../screenshots/archive/...)`
  相对路径），让 IDE 预览 md 时可直接看图——只写文件名不算存档，图要能一键打开。
- 截图：`screenshots/archive/<主题>/`（存验收证据），过程截图调试结束后清理。
- 素材源文件与生成 prompt：`temp/style-loop/production/batch-*/`（含各子目录），
  处理脚本入 `tools/`（长期维护）。

## 五、反例（本次规范产生的原因）

2026-10-27 液体液面帽优化：AI 抽样了 1 个关卡的部分瓶子的局部区域，
像素采样只做了接缝色差一项，与参考图的对比是印象分，即宣布"可以了"。
用户复看仍发现问题。教训：**验收的完整性由矩阵决定，不由已发现的缺陷决定。**
