# 坏味道检查清单（code-optimize-review）

审查时逐项过，命中的记录：`文件:行` + 问题 + 严重度（高/中/低）。
严重度只反映"值得改的程度"，是否列入方案由收益/成本比决定。

---

## 1. 通用代码坏味道

| 检查项 | 判据 | 严重度 |
|---|---|---|
| 长函数 | 单函数 > 40 行，或一个函数里做"解析 + 判定 + 执行 + 通知"多件事 | 高 |
| 上帝类/上帝节点 | 单文件 > 300 行且职责 > 2 个（用"它负责什么"说不清就是多职责） | 高 |
| 深嵌套 | if/for 嵌套 > 3 层；用卫语句/提前 return 可消 | 中 |
| 魔法数字/字符串 | 裸写数值/状态码无常量名（如 `if chips == 200`） | 中 |
| 重复代码 | 相同逻辑出现 ≥ 2 处（牌力展示、筹码格式化、座位定位等高危区） | 中 |
| 长参数列表 | 参数 > 4 个，应改对象/字典/Resource | 低 |
| 注释弥补命名 | 注释在解释"代码在做什么"而非"为什么这样做" | 低 |
| 否定式逻辑 | 大量 `not x or not y` 组合判断，应提取谓词函数 | 低 |

## 2. 分层违规（一票否决，必列）

| 检查项 | 判据 |
|---|---|
| core 碰场景树 | `scripts/core/` 内出现 `extends Node`、`add_child`、`get_node`、`await get_tree()` |
| 表现层做判定 | presentation 内出现牌力比较、合法性判断、底池/名次计算 |
| 数据层持可变状态 | `card_data/hand_rank_data/blind_schedule` 出现可变成员变量 |
| autoload 塞业务 | autoload 里有规则/流程逻辑而非纯全局薄状态 |
| 依赖反向 | core 引用 presentation；或未用 `preload()` 显式路径 |

## 3. Godot 惯用法

| 检查项 | 判据 | 严重度 |
|---|---|---|
| 跨层硬路径 | 兄弟/跨分支节点用 `$A/B/C` 或 `get_node("深/路径")` 互访 | 高 |
| 兄弟直连 | 控件间互相调用，而非发信号由共同父节点中转 | 高 |
| 上帝节点 | `main.gd` 直接操作桌面/座位/牌/UI 的深层细节 | 高 |
| 信号向上调用向下 | 子节点直接调父节点方法（应发信号） | 中 |
| 场景不自包含 | 场景离开当前父节点就无法运行（依赖外部节点路径） | 中 |
| 滥用继承 | 用 `extends` 加功能，而场景组合可以更简单 | 中 |
| 滥用 Autoload | 为了"全局能访问"就把东西挂 autoload | 中 |

## 4. 逻辑设计

| 检查项 | 判据 | 模式映射 |
|---|---|---|
| 隐式状态机 | 单个长 `match`/if-else 链驱动阶段流转，阶段行为散落 | 状态（State） |
| 检查与执行耦合 | 动作合法性与执行写在一起，难以单独测试合法性 | 命令（Command） |
| 动作不可序列化 | 无法把一手牌的操作序列存下来回放/调试 | 命令（Command） |
| AI 决策硬编码 | 决策权重写死在函数里，无法配置不同风格 | 策略（Strategy） |
| 事件数据不自足 | 消费事件后还要回头查状态机才能渲染 | 观察者（事件带全量数据） |
| 随机性不可注入 | 逻辑层直接 `randi()`/`shuffle()` 而非注入 seed | （架构约束，必列） |
| 数值硬编码 | 起始筹码/盲注/奖励写进逻辑层而非 `resources/tournaments/*.jsonc` | （架构约束，必列） |

## 5. 可读性与可测性

| 检查项 | 判据 | 严重度 |
|---|---|---|
| 测试缺口 | 核心规则函数没有对应用例（正常 + 边界） | 高 |
| 不可复现 | 同一 seed 无法复现同一局（回归调试地基塌了） | 高 |
| 命名不一致 | 同一概念多个叫法（pot/pool、seat/chair 混用） | 中 |
| 断言弱 | 测试只断言不崩溃，不断言具体值 | 中 |
| 死代码 | 注释掉的代码块、永远为 false 的分支、无引用的函数 | 低 |
