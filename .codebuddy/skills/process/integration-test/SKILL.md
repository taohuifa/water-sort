# 游戏开发集成验证

拉起游戏，执行三层验证闭环（three-layer verification loop），定位并修复问题。适用于 impl-developer 交付后的集成阶段。

## 三层验证闭环

按顺序执行，前一层失败先修复再进入下一层：

### 第 1 层：逻辑回归（headless）

```
godot --headless --path . --script res://tests/<回归脚本>.gd
```

- 断言核心玩法规则正确性（以项目 PRD 验收标准为准）；
- 关注性能 / 平衡性统计输出（如对局时长分布）；
- 退出码非 0 或出现 FAIL 输出即失败。

### 第 2 层：UI 冒烟（headless 模拟点击）

```
godot --headless --path . --script res://tests/<冒烟脚本>.gd
```

- 验证主流程流转（如菜单 → 对局）；
- **若本功能的集成场景未被现有脚本覆盖，先补充 `tests/` 下的集成测试脚本再跑**（测试脚本不放项目根目录）。

### 第 3 层：截图验收（自动演示）

```
godot --path . --quit-after N -- <演示参数> <截图参数>
```

- 检查截图输出目录的分阶段截图，肉眼确认视觉表现；
- 仅验证视觉，不作为规则正确性依据；
- 辅助命令：AI 自动演示模式（可交互观察）。

> 以上为 Godot 项目命令示例；其他项目以其实际演示 / 截图启动参数与输出目录为准（见项目 README 命令速查）。

## 修复循环

1. **定位**：从失败层的报错 / 断言输出定位到具体文件与行；
2. **修复**：read_file 读取相关代码 → replace_in_file 定向最小修改；修复逻辑层问题必须同步检查测试断言是否正确；
3. **重验**：修复后重跑失败层；若改动涉及规则，逻辑回归也必须重跑；
4. **回归确认**：三层全部通过后，完整再跑一遍确认无回归。

## 诊断代码纪律（可逆性优先）

- 修复未验证通过前，**严禁删除任何诊断 / 调试代码**——它们是后路；
- 正确顺序：修复 → 验证通过 → 确认问题解决 → 清理诊断代码（约定 `# DIAG:` 前缀）→ 清理后重跑回归；
- 新增诊断代码一律加 `# DIAG:` 前缀注释，便于统一清理。

## 输出要求

- 验证报告写入 `docs/integration/<YYYYMMDD>-<特性名>.md`：各层结果、失败现象、修复明细、诊断代码清理记录、遗留问题；
- 回复中完整呈现三层验证结果与修复内容，明确说明"诊断代码已清理 / 保留（原因）"。
