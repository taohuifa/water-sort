# 代码审查清单

> 逐项检查，结果记入审查报告。任一"架构合规"项失败即为严重（Blocker）问题。

## A. 架构合规（Blocker 级）

> 层与文件归属以项目 README 分层说明为准；未定义时按典型四层检查。

- [ ] A1 逻辑层无引擎节点依赖：规则引擎中无 `extends Node` / `add_child` / `await get_tree()` / `get_node()` / `get_tree()` / 场景树访问
- [ ] A2 表现层无规则判定：视图 / UI / 动画代码中无数值计算、步数推进、规则判定逻辑
- [ ] A3 数据层纯度：常量与纯函数模块无可变状态
- [ ] A4 事件完整性：事件携带表现层所需的全部数据（无需回查规则）
- [ ] A5 职责归位：数值与配置表在数据层，判定在逻辑层，消费在表现层

## B. 正确性与边界（对照项目 PRD 玩法规则逐条检查）

- [ ] B1 核心规则：正常触发与不触发条件正确
- [ ] B2 连锁 / 叠加：连续效果、多实体同格 / 叠放、规则交叉时优先级正确
- [ ] B3 终局：数值越界处理、精确终止、胜利 / 失败结算正确
- [ ] B4 特殊回合机制：额外行动、跳过、次数上限（若规则定义）
- [ ] B5 回合流转：玩家 / 实体顺序、无有效操作时的处理
- [ ] B6 随机性：随机源可注入，测试中固定 seed / 指定数值
