# 游戏开发 PRD 生成与需求拆分

为游戏项目生成需求 PRD（Product Requirements Document）并拆分需求。产出物只包含文档，不改动代码。可跨游戏项目复用。

## 执行流程

1. 读取 `README.md` 与 `docs/requirements.md`（若存在），掌握现有玩法规则与技术约束。
2. 提取用户输入中的功能点、规则数值、边界条件。信息不足时列出问题清单（开放问题）向用户确认，禁止脑补关键数值（如判定条件、触发概率、数值阈值）。
3. 按 `references/prd-template.md` 的结构生成 `docs/prd/PRD-<特性名>.md`。
4. 在 PRD 末尾完成需求拆分表（见下文拆分方法）。
5. 在回复中完整呈现功能清单与拆分表，等待用户确认；确认前不得进入实现。

## 需求拆分方法

按项目架构自底向上拆分（以项目 README 的分层说明为准，典型为四层），保证每条子需求独立可验证：

| 层 | 职责 | 拆分粒度 |
|---|---|---|
| 数据层 Data | 静态常量 / 配置表 / 纯函数 | 一组常量表 / 纯函数 |
| 逻辑层 Logic | 规则引擎（零引擎节点依赖，可无头 headless 运行） | 一条可独立验证的规则 |
| 胶水层 Glue | 事件队列 + 阶段状态机 | 一类事件定义 + 状态迁移 |
| 表现层 Presentation | 视图 / UI / 动画（只消费事件） | 一个界面或一个动画消费路径 |

每条子需求必须标注：

- **ID**：F-01 递增
- **分层**：数据 / 逻辑 / 胶水 / 表现
- **优先级**：P0 必须 / P1 应该 / P2 可选
- **依赖**：前置子需求 ID（数据层通常无依赖）
- **验收方式**：headless 回归断言 / UI 冒烟 / 截图验收 / 人工确认（具体测试脚本与启动命令以项目 `tests/` 目录及 README 为准）

## 验收标准写法

验收标准必须可测试，与项目三层验证闭环对齐：

- 写成"给定…当…则…"格式（Given / When / Then）；
- 每条标准对应一个 headless 可断言结果，或明确标注"人工确认"；
- 涉及概率 / 数值的规则，同时给出测试方法（如批量跑 N 局统计分布）。

## 目录约定

- PRD 输出到 `docs/prd/`，一个特性一个文件；
- 后续实现文档（`docs/design/`）、审查报告（`docs/review/`）以 PRD 文件名为锚点互相引用。
