# PRD 模板：PRD-<特性名>.md

> 复制本模板到 `docs/prd/PRD-<特性名>.md` 后填写。删除不适用的段落，禁止删除"验收标准"与"需求拆分"两节。

## 1. 背景与目标

- 背景：为什么做这个功能（用户价值 / 玩法缺口）。
- 目标：一句话说明完成后达成什么状态。
- 非目标（Out of Scope）：明确本次不做什么，防止范围蔓延。

## 2. 玩法规则

- 规则描述：完整描述新增 / 变更的规则。
- 数值定义：所有判定数值（步数、概率、阈值、次数），逐项列清楚，不留"待定"。
- 边界条件：新规则与现有规则交叉时的判定优先级（逐条列出本项目的既有核心规则）。

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|

## 4. 非功能需求

- 性能：headless 批量跑 N 局的时长预算；
- 兼容：与现有存档 / 配置 / AI 演示模式的兼容性；
- 可维护性：常量表是否可独立调整（数值平衡改动不触碰逻辑代码）。

## 5. 验收标准

采用 Given / When / Then 格式，每条标注验收方式：

- AC-01：给定…，当…，则…（headless 断言）
- AC-02：…（UI 冒烟）
- AC-03：…（截图验收）
- AC-04：…（人工确认）

## 6. 开放问题

- 需要用户决策的问题清单，每条给出可选方案与建议。
